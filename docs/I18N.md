# I18N.md

Internationalization in scaffolded projects.

---

## Stack

- **i18next** (web)
- **react-i18next** (hooks)
- Default locale: `en` (English)
- Bundled locale: `am` (Amharic — useful for Ethiopian market / Chapa users; remove if unused)

---

## Files

```
apps/web/src/shared/i18n/
├── config.ts          (tenant app)
├── config-admin.ts    (super admin app — separate i18n instance)
└── locales/
    ├── en.ts
    └── am.ts
```

Each locale file exports a `Record<string, string | object>` of nested keys.

---

## Adding a new locale

1. Create `apps/web/src/shared/i18n/locales/fr.ts` with same shape as `en.ts`
2. Add to `config.ts`:
   ```typescript
   import fr from "./locales/fr";
   i18n.init({
     resources: {
       en: { translation: en },
       am: { translation: am },
       fr: { translation: fr },
     },
     fallbackLng: "en",
   });
   ```
3. Add toggle in `LanguageSwitcher` component.

---

## Removing a locale

To strip Amharic entirely:
1. Delete `apps/web/src/shared/i18n/locales/am.ts`
2. Remove from `config.ts` + `config-admin.ts`
3. Remove `nameAm`/`subjectAm`/`bodyHtmlAm` columns in Prisma schema (Plan, SystemEmailTemplate, NotificationTemplate, CustomRole) — or leave nullable + ignore
4. Update `seed-plans.ts` and other seeds — drop `nameAm` arg

## Adding a key

```typescript
// en.ts
export default {
  sidebar: {
    dashboard: "Dashboard",
    projects: "Projects",        // <-- new
  },
};

// component
const { t } = useTranslation();
return <h1>{t("sidebar.projects")}</h1>;
```

Always add `defaultValue` for safety:
```typescript
t("sidebar.projects", { defaultValue: "Projects" })
```

## Backend i18n (emails)

System email templates store English + Amharic side-by-side:

```prisma
model SystemEmailTemplate {
  key        String  @unique
  subject    String
  bodyHtml   String
  subjectAm  String?
  bodyHtmlAm String?
}
```

`DunningService` picks the right column based on org's `OrganizationSettings.language` (default `en`). Add more languages by extending the schema with more `subjectFr` / `bodyHtmlFr` columns, OR migrate to a single `translations Json` column for full flexibility.

## Naming convention

- `sidebar.*` — left nav items
- `auth.*` — login, signup, password reset, verify email
- `settings.*` — settings pages
- `billing.*` — billing UI
- `admin.*` — super admin panel
- `common.*` — buttons, errors, generic
- `<feature>.*` — per-domain (projects.*, etc.)
